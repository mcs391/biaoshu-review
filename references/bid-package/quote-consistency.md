# 报价与跨文件一致性复核

## 一、两种一致性必须分开

1. **跨文件品牌型号一致性**：招标清单、投标明细、技术响应、报价、声明函、证书是否写成同一对象。
2. **报价内部同品牌型号单价一致性**：同一报价文件中，同品牌同型号是否出现不同单价。

两个结论必须在工作区分别列出；“跨文件一致”不能替代报价内部反向归组。

## 二、正向逐项

以采购清单序号为主键，逐项核对：名称、品牌、型号、单位、数量、单价、合价、制造商、产地、中小企业属性。计算：

- 数量×单价=合价；
- 分项合计=开标一览表总价；
- 数字总价=大写总价；
- 报价文件总价=平台填写总价（平台值需要用户或页面证据）；
- 报价内容=商务技术和资格声明内容。

## 三、反向归组

先运行：

```bash
python scripts/check_bid_price_consistency.py <报价文件.tables.json> --out workspace/<项目>.price_consistency.json
```

第一层按品牌+型号强制归组，不看名称和单位；第二层按品牌+型号+单位辅助解释。

- 名称不同不能跳过：同一硬件可能被写成“虫情监测终端”“数据采集系统”等不同名称。
- 单位不同不能跳过：台/套/项差异只是计价范围线索。
- “批/项/宗”等汇总单位要展开数量、配件、长度和服务范围。
- 型号为“配套/定制/无”时脚本会跳过自动分组，必须人工按品牌、配置和清单顺序复核。
- PDF表格提取为0张时，不能写“检查通过”；应人工结构化报价表或将报价行与技术清单顺序联接后再分组。

处理口径：

- 同品牌同型号异价：列为重大一致性风险，回查配置、计价范围、报价修正、异常低价和虚假材料条款；招标未规定自动无效时不直接判废标。
- 无重复品牌型号组：明确写“扫描N项，未形成重复组”，不能只写“未发现问题”。
- 修正型号、制造商或价格时，同步回写投标明细、技术响应、报价、产品声明和中小企业声明。

## 四、制造商与声明字段

- 报价表要求制造商全称、是否中小企业时，空白字段单列，不因有价格而忽略。
- “国产”“华数”“美的”等品牌或渠道名不能替代企业全称。
- 安装、培训等服务项是否填写制造商要按表格口径说明；不要把服务强行写成制造产品。
- 本国产品声明和中小企业声明应从报价表反向核对，防止遗漏附件、扩大声明范围或把投标人误写成制造商。

## 五、工作区固定输出

`## 报价一致性与反向分组` 主表至少含：序号、产品名称、品牌、型号、单位、数量、单价、合价、制造商、声明状态、归组键、核查结果。

表后记录：扫描总项数、有效品牌型号项数、占位型号项数、重复组数、异价组数、脚本是否完整扫描。
