# 签章投标文件终稿复核

当用户同时提供招标文件和已经签章的资格、商务技术、报价等 PDF 时，执行本流程。目标是确认“签章成品是否仍保留完整响应”，不把版式抽检或签名结构检查误写成平台验签结论。

## 一、先建立三层基准

1. **招标规则基准**：先按主流程生成 `lines.txt`、`hits.json` 和工作区，所有废标、评分、▲/★、时间事实仍引用招标文件行号。
2. **未签章内容基准（如有）**：用于判断签章前后是否丢页、换页、删表、改型号或改金额。
3. **签章 PDF 成品**：这是最终审查对象。用户只给签章 PDF 时，不假设其与之前 Word 相同。

## 二、签章包固定十检

### 1. 上传槽与文件组成

- 对照招标文件要求的资格、商务技术、报价、备份等组成，列出每个实际 PDF 的文件名、页数、大小和用途。
- 两个上传槽放入内容相同的完整资格文件，不自动判无效；记录“重复上传”并确认每个槽是否允许完整包。
- 发现缺少一个组成文件、仅有备份文件、文件加密无法读取或0页时，按招标条款分级。

### 2. PDF签名结构

运行：

```bash
python scripts/inspect_signed_bid_package.py <资格.pdf> <商务技术.pdf> <报价.pdf> --out workspace/<项目>.signed_package.json
```

核查：

- `/FT=/Sig` 签名域是否存在；
- `/SubFilter`（如 `/GM.sm2seal`）是否存在；
- `/ByteRange` 是否覆盖到文件末尾，是否有签名后追加字节；
- PDF 是否加密、能否打开、页数是否异常；
- 精确文件重复和标准化文本重复。

边界：结构正常只能写“发现电子签名域且未见签后追加字节”。不得写“证书有效”“签章真实”或“平台验签通过”，除非已在政采云/交易平台或可信验签工具中实际验证。

### 3. 项目标识

逐份检查项目名称、项目编号、标项、采购人、投标人名称、日期。重点抽查封面、投标函、授权书、报价表、承诺函、制造商证明。

### 4. 资格完整性

逐项对照招标资格格式和资格审查表，至少检查：

- 营业执照及有效期；
- 法定代表人身份证正反面；
- 授权委托书、代理人身份证及授权期限；
- 政府采购法第二十二条承诺、信用记录；
- 联合体、分包、中小企业等条件是否适用；
- 需要签署、盖章、日期的位置是否可见。

身份证号码等敏感信息只确认存在与清晰，不在报告中抄录。

### 5. 符合性与▲实质响应

- 全量列出招标文件范围内的▲条款，不因签章文件页数多而抽样省略。
- 对每项记录“投标响应页+证明页+招标行号”。
- “响应表写满足”不等于完成证明；招标要求检测、截图、证书、承诺时必须找到附件。
- 证明存在但型号、主体、有效期、数量或适用范围不匹配时，列为证据链风险。

### 6. 报价勾稽

- 核对唯一报价、大小写、数量×单价=合价、分项合计=总报价、总价与平台填写值。
- 核对报价是否超过预算/最高限价，是否漏项或数量不足。
- 报价表制造商、是否中小企业、产地、品牌、型号等字段为空时单独列出；不能只因有价格就视为“内容完整”。

### 7. 同品牌型号反向归组

按 `references/bid-package/quote-consistency.md` 执行。无论产品名称和单位是否不同，先按品牌+型号归组，再按品牌+型号+单位解释。结果必须单独成行，不能与“跨文件型号一致”合并。

### 8. 声明函

专项核对中小企业声明、本国产品声明、残疾人福利性单位、监狱企业等：

- 声明是否属于资格条件、价格优惠条件，还是不适用可不提供；
- 产品名称、型号、制造商/生产厂、厂址、行业、企业规模是否与报价和证明一致；
- 不适用的空白声明是否明确写“无/不适用”，是否仍被误盖章成肯定声明；
- 声明范围是否不必要地扩大到无法证明的产品。

### 9. 证据链

按 `references/bid-package/evidence-chain.md` 核对质保、节能环保、3C、检测、校准、软著、体系认证和产品网页。尤其区分“原厂直接承诺”“投标人承诺购买”“商业商品页”“已购买/已激活凭证”。

### 10. 平台与外部条件

以下只能列为“待平台/外部确认”，不能离线宣称通过：

- 政采云上传、加密、递交、解密回执；
- CA证书信任链和签章主体；
- IP、MAC、设备硬件、联系人及其他投标人文件比对；
- 同品牌投标人数量；
- 信用网站和证书网站在评标时的在线状态。

## 三、视觉抽检

签章 PDF 至少渲染并检查：封面、资格证照、授权、投标函、符合性表、报价总表、报价明细、关键▲证明、质保材料、声明函、末页。630页等超长文件不能逐页肉眼检查时，先文本定位关键页，再抽取页首/页尾和随机页；报告写明抽检范围，不写“全630页视觉无误”。

## 四、风险语言

按以下口径输出，不直接替评委作决定：

| 分类 | 使用条件 | 推荐表述 |
|---|---|---|
| 已确认触发事实 | 文件内容明确满足招标无效条款的触发条件 | “发现与行X无效条款直接对应的事实，需立即复核” |
| 高风险 | 真实性、实质响应、漏项、型号或证据适用性存在明显矛盾 | “存在被援引为无效/重大偏离的风险” |
| 评分风险 | 最低实质要求已满足，但加分档证据不足 | “基础响应不受影响，X分档可能不认” |
| 格式/检索风险 | 页码、目录、定位、字段完整性问题 | “增加评委检索或完整性争议，通常不单独等同废标” |
| 平台/外部未验证 | 本地文件无法判断 | “必须由交易平台/在线查询/其他投标人比对确认” |
| 合同义务 | 中标后才触发 | 单独放入合同条款，不混进当前废标清单 |

## 五、工作区固定新增表

终稿审核必须新增：

- `## 当前签章投标文件核对结果`
- `## 报价一致性与反向分组`
- `## 证据链复核`
- `## 风险复核`
- `## 平台与外部待确认`

Excel仍由 `run_pipeline.py verify` 生成；签章结构 JSON 与 Excel、Markdown一并交付。
